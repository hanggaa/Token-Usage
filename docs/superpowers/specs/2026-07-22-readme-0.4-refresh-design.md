# README 0.4 Refresh Design

## Goal

Refresh `README.md` so it accurately represents Token Usage Tracker `0.4.0` for both extension users and contributors. The README should explain the current product value, local-only privacy model, supported sources, measurement limitations, installation workflow, settings, commands, and development workflow without becoming a full technical specification.

## Audience and Reading Order

Use a layered structure:

1. Lead with user value and the fastest path to installation.
2. Explain the dashboard, usage controls, privacy, and measurement accuracy.
3. Provide a compact configuration and command reference.
4. End with contributor setup, verification, packaging, visual QA, and project structure.

This order lets extension users stop after the operational sections while contributors can continue into implementation details.

## Content Structure

### Product overview

Describe the extension as a private, local-first token usage tracker for Codex CLI, OpenCode CLI, and Antigravity IDE. State that it imports local histories into a local SQLite index and does not transmit usage data.

### Current capabilities

Summarize the current dashboard rather than presenting `0.4.0` as a temporary announcement:

- Today, Last 7 Days, and All Time summaries.
- One Daily, Weekly, and Monthly calendar aggregation selector.
- Current-period token budgets with `On track`, `Approaching limit`, and `Budget exceeded` states.
- Top source, project, and model contributors.
- Unusually heavy turns compared with the user's own recent local history.
- Import Health, source filters, the turn table, and turn details.
- Exact, estimated, partial lower-bound, and unavailable measurement qualities.

Include a short **What's new in 0.4.0** section that highlights budgets, contributor explanations, unusually heavy turns, and conflict-safe VS Code settings synchronization.

### Privacy and accuracy

Retain the existing privacy guarantees and per-source accuracy table. Clarify that budgets and insights are calculated locally, warnings never block source tools, and full project paths are used only as local metadata. Preserve the Antigravity limitations and lower-bound explanation.

### Installation and first use

Update the stale VSIX filename to `token-usage-tracker-0.4.0.vsix`. Include both VS Code's **Install from VSIX...** flow and the optional command-line installation command. The first-use path is:

1. Install the VSIX.
2. Open **Token Usage** from the Activity Bar or command palette.
3. Run **Token Usage: Refresh Now** to import persisted histories.
4. Optionally set Daily, Weekly, and Monthly budgets from the dashboard or VS Code Settings.

Do not retain the obsolete instruction to rebuild the index solely for the earlier Antigravity prompt-cleanup migration.

### Settings and commands

Add a compact table covering:

- Source enable switches.
- Optional source-root overrides.
- Optional tracker database path.
- Background refresh enablement and interval.
- Daily, Monday-Sunday weekly, and calendar-month budgets; `0` disables a budget.
- Prompt retention: `full` or `countsOnly` for future imports.

List all five contributed commands using their exact manifest titles.

### Contributor guide

Keep the existing `npm install`, `npm run verify`, `npm run package`, and visual-QA commands. Add a short project map for `src/adapters`, `src/services`, `src/storage`, `src/webview`, `webview/src`, and `tests`. State that `npm run verify` runs tests, both TypeScript checks, and the production build.

## Writing Style

- Use concise, descriptive headings and short paragraphs.
- Prefer operational wording over marketing claims.
- Use tables only for repeated mappings such as source accuracy and settings.
- Preserve exact command and setting identifiers in code formatting.
- Avoid implementation detail that belongs in the design specs or implementation plans.
- Avoid claims about pricing, cost conversion, cloud synchronization, notifications, or automatic blocking because those features do not exist.

## Acceptance Criteria

- README identifies the release as `0.4.0` and uses the correct VSIX filename.
- Every current dashboard capability is represented accurately.
- Calendar weeks are described as Monday through Sunday.
- Budget status meanings and zero-disabled behavior are clear.
- Contributor and heavy-turn insights are explained without labeling usage as wasteful.
- Privacy, local storage, source read-only behavior, and measurement-quality limits remain accurate.
- Every contributed setting and command is discoverable.
- Contributor verification and packaging commands match `package.json`.
- Obsolete `0.2.1` installation and one-time migration wording is removed.
- Markdown structure, tables, links, and command fences are valid.

## Out of Scope

- Product behavior changes.
- New screenshots or redesigned visual assets.
- Publishing the VSIX or pushing commits to a remote.
- Duplicating the complete Token Budget and Insights design specification.
